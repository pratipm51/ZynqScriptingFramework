## 1. Introduction
This framework provides a structured, version-control-friendly environment for Zynq-7000 FPGA development. It prioritizes **VHDL** for logic and **C** for software, utilizing a "Project-less" approach that keeps your Git repository free of Vivado/Vitis "junk" files.

### Why this exists:
Zynq boards (like the EBAZ4205) require the ARM Processor (PS) to be instantiated to provide clocks and resets to your VHDL logic. This framework bridges the gap between the necessary GUI configuration and the efficiency of a CLI-based build process.

## 3. The Two-Phase Workflow

### Phase 1: The Initialization (GUI Required)
Since Zynq requires a Processor System (PS) configuration, you must initialize the hardware visually once.

1. **Reconstruct/Open**: Run `make edit-hw`.
2. **Create Design**: If it's a new project, create a Block Design named **`system`**.
3. **Configure**: Add the **Zynq7 Processing System** IP. Run "Block Automation" to apply board-specific settings (DDR, MIO).
4. **Logic Bridge**: If using custom VHDL, add your VHDL module to the Block Design or use the PS clocks (`FCLK_CLK0`) to drive your logic.
5. **Freeze to Script**: In the Vivado Tcl Console, run:
   ```tcl
   write_bd_tcl -force ./scripts/ebaz_bd.tcl
   ```
   *This command converts your GUI clicks into a text script that Git can track.*

---

### Phase 2: The Development Loop (CLI)
Once Phase 1 is complete, you rarely need the GUI. Stay in your favorite text editor and use the terminal.

| Command | Action |
| :--- | :--- |
| `make hw` | Synthesizes VHDL, implements design, and exports `.xsa` |
| `make sw` | Compiles C code using Vitis and generates platform/app |
| `make` | Builds both Hardware and Software in sequence |
| `make program` | Uses JTAG to flash the bitstream to the board |
| `make clean` | Wipes all build artifacts and temporary tool logs |

## 4. Detailed Command Reference

### `make edit-hw`
Launches Vivado and automatically sources your `scripts/ebaz_bd.tcl`. This reconstructs your exact environment from the script. If the script doesn't exist yet, it opens an empty Vivado instance.

### `make sync-scripts`
A reminder command. It displays the exact Tcl command you need to run *inside* Vivado to save your changes back to the repository. **Always run this before committing your Git changes.**

### `make program`
Detects your connected JTAG cable, identifies the Zynq chip, and programs it with the latest `system.bit` file.

## 5. VHDL Integration
The framework is configured for **strict VHDL**. 
* The build script (`build_hw.tcl`) automatically finds all `.vhd` and `.vhdl` files in `src/hdl/`.
* If no Block Design is found, the framework defaults to a file named `top.vhd` as the top-level entity.

## 6. Git Best Practices
This repository uses a **Whitelist .gitignore**. 
* **Only tracked files**: `scripts/`, `src/`, `sw/`, `Makefile`, and Documentation.
* **Ignored junk**: `.Xil/`, `hw_build/`, `vitis_ws/`, and all `.log` or `.jou` files.

**Before you commit:**
1. Run `make clean` to ensure no local paths are leaked into scripts.
2. Ensure you have run `write_bd_tcl` if you modified the Block Design.
3. `git add .` followed by `git commit`.

## 7. Troubleshooting
* **Clock not running**: Ensure the Zynq PS is instantiated and the `FCLK_CLK0` is connected to your VHDL clock port.
* **Vitis build fails**: Ensure `make hw` was successful first; the software build requires the `.xsa` file generated by the hardware build.
* **Vivado Version Error**: The `ebaz_bd.tcl` is version-locked. If you upgrade Vivado, you may need to manually update the version string at the top of the Tcl script or recreate the BD.
